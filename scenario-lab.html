전체 메모리 지도에서 저장량과 이동량을 함께 보고, 한 요청의 적중·미스·교체 과정을 따라갑니다. 가정한 상황과 B200에서 측정한 사례를 직접 바꿔 비교하세요.

Ledger의 결정 단위“전체의 몇 %를 담는가”가 아니라 상주 바이트 1개가 스텝마다 몇 바이트의 off-chip 이동을 없애는가입니다. 용량 커버리지와 기존 캐시가 잃는 공간도 함께 봅니다.

모델 조건 · 계산값

‘기존 L2 분할’의 persisting 예약 영역은 cudaLimitPersistingL2CacheSize + cudaAccessPolicyWindow가 주는 힌트입니다. 캐시 라인을 고정(pin)하거나 상주를 보장하지 않으며, 남는 예약 용량은 일반 접근이 씁니다.

캐시 사본이 생겨도 HBM 원본을 자동으로 빼지 않습니다. HBM 회색은 activation·작업 공간·예약량 등이 빠진 부분으로, 실제 빈 공간을 뜻하지 않습니다.

가정 기반 경로 실험

A·B는 설명용 데이터 조각입니다. 실제 GPU 주소 기록이나 캐시 라인 크기가 아닙니다. 교체는 단순 LRU, 쓰기는 write-back으로 가정합니다. 되쓰기는 수정 가능한 상태 A의 예시이며 모델 가중치 갱신이 아닙니다. ‘미리 배치한 SRAM 데이터’는 단계 0(HBM → 근접 tier 최초 적재)과 단계 1(근접 tier → 연산부 서비스)을 순서대로 재생하며, 위 체크를 끄면 이미 채워진 상태에서 시작합니다. ‘같은 양 비교’는 미리 채워둔 상태이며 최초 적재 비용은 제외합니다.
